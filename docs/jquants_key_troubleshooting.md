# J-Quants key_missing の修正

## 原因として確認したコード上の不具合

`key_missing` はAPIへリクエストする前に、アプリがキーを読み込めなかったときのエラーです。APIキーの不正を示す401、無料プランの権限不足403、回数制限429とは異なります。

旧実装には次の問題がありました。

- `st.secrets` の標準探索場所は起動時の作業フォルダに影響され、別フォルダから絶対パスでStreamlitを起動すると、アプリ内の `.streamlit/secrets.toml` を見つけられない場合がある。
- 設定の解析等で一般例外が発生すると空文字で終了し、有効な環境変数があっても参照されない。
- 書式不正・キー名不一致・ファイル未配置がすべて未設定としか表示されない。

利用者のWindows PCの設定ファイルをこちらから直接調査した結果ではありません。上記不具合を再現し修正しました。実際のPCでは修正版の診断表示で配置と状態を確認してください。

## 修正後の優先順位

1. **アプリ本体の場所**を基準にした `.streamlit/secrets.toml` を読む（作業フォルダに依存しない）。
2. `st.secrets` の設定を参照する（ユーザー共通設定等を維持）。
3. `JQUANTS_API_KEY` 環境変数を参照する。ファイルが壊れていても有効な環境変数があれば利用できる。

トップレベルの `JQUANTS_API_KEY`、または `[jquants]` 内の `api_key` に対応。WindowsエディターのUTF-8 BOMにも対応します。読み込み時に再読するため、プロジェクトの設定ファイルを修正した後は、一覧の更新ボタンで反映できます。Streamlit共通設定やプロセスの環境変数を変更した場合は、アプリを停止して起動し直してください。

## 画面で確認する

1. 最新版へ更新し、「AI銘柄探索」を開きます。
2. 「日本株の自動探索」→「接続・公式資料」→ **「J-Quants APIキーの読み込み状態（キーは表示しません）」**を開きます。
3. 「読み込み元」「設定ファイルの場所」「あり/なし」「起動時の作業フォルダ」を確認します。キー本体・末尾・長さ・ハッシュは表示しません。
4. 「なし」の場合は、表示されたアプリフォルダの `.streamlit` に、以前使えていた `secrets.toml` をPC内でコピーします。他の古い版のフォルダにだけ保存されている状態では読めません。
5. 「あり」でもキー名が見つからない場合は、TOMLの配置を確認します。`JQUANTS_API_KEY` をトップレベルで使う場合は、`[theme]` 等の別セクションより前に書きます。`secrets.toml.txt` になっていないかも確認してください。
6. 「読み込み済み」になったら「銘柄一覧を取得・更新」を押します。これは設定が読めた状態で、API側の認証成功を保証する表示ではありません。

APIキーや設定ファイル本文をチャット・画面写真・GitHubへ送らないでください。診断表示には本文を出しません。

## 起動・認証・無料プラン

既存の `起動.bat` はアプリフォルダへ移動してから起動します。修正ではこれを維持し、アプリ全体の作業フォルダや保有DBの保存場所を変更していません。

接続先は `https://api.jquants.com/v2`、認証は **`x-api-key` ヘッダー**。旧V1のメール/パスワード・リフレッシュトークン・Bearer認証は使いません。キーをクエリーへ入れず、リダイレクトも許可しません。

無料プランへ配慮し、このアプリプロセス全体で同一キーに対する実HTTP通信を保守的に60秒あたり5回までに制限します。これは契約上の上限値を断定するものではありません。APIの429ではRetry-Afterを使って待機（最低60秒、最大1時間）。自動連続再試行をせず、途中の一覧を確定保存しません。画面やクライアントを作り直しても同じプロセスの待機状態は引き継がれます。他のPCやプロセス、他のAPI利用アプリとの回数共有はできません。

一覧の24時間キャッシュ、段階取得、遅延価格の参考表示は維持しています。提供期間外の日付やデータ権限の問題はAPIキーの配置とは別に確認します。

## テストと実接続の範囲

既存161件を維持し、合計174件成功。別作業フォルダ・プロジェクト優先・Streamlit共通設定・環境変数へのフォールバック・BOM・設定再読・書式不正・秘密情報非表示・V2ヘッダー・429待機を検証。Streamlit画面の一覧更新ボタンから、設定ファイルを読んで架空APIの一覧をDBに保存し、次の更新はキャッシュを使うところまで検証しました。

開発環境には実際のsecrets.tomlも環境変数のキーもないため、実キーを使ったJ-Quants接続とWindows実機は未検証です。テストは架空キーと架空レスポンスで実行しています。保有資産・積立・ポートフォリオ分析の実装とDBスキーマは変更していません。
