# 取引取り込みと会計（Phase 2）

## 取引CSVがない場合

保有資産 → 新しい保有残高を登録（初期残高・CSV不要）で数量/価格/参考取得原価等を入力する。
取得原価・価格・USD為替の空欄は不明として保存できる。取引は作らず、既存6画面を利用できる。
あとから取引を取り込んでも直接残高を優先。コード未記入でも同口座/種別/通貨で同名称、または同コードなら同一候補として取引側を加算せず照合を求める。候補の同一性を勝手に確定しない。

## SBI CSV

データ管理 → SBI取引CSV・列マッピング。
1. 利用者が公式画面から取得したCSVをアップロード（UTF-8/BOMまたはCP932、5MB、10,000行まで）。
2. 実際のヘッダー行（1〜51）と区切り（カンマ/タブ/セミコロン）を指定し、画面で実列を確認。
3. 取引日、銘柄、売買、数量、単価、手数料、税額、口座等の列を対応付ける。商品種別/通貨/口座は、ファイル全体で確定している場合だけ固定値にできる。
4. 値マッピングJSONで例 `{"kind":{"買付":"buy","売却":"sell"},"account":{"特定預り":"特定"}}` を指定。これは値の変換例でありSBIの様式定義ではない。
5. 日付形式と確認プレビューを照合。buy/sell以外や未知区分は止める。数値の桁区切りや通貨記号は自動除去しないので、必要なら利用者が値を整える。推測補完は行わない。
6. 費用の通貨や内訳、口座、欠損を確認して保存。既存と同じ取引はスキップし、矛盾がある場合は全件を保存しない。

固定の実SBI列セットは未確認で、様式別に自動判定するアダプターではない。現時点のsbi.pyは利用者確認型の汎用マッピング経路。実ファイルの確認後に固定アダプターを追加できる。

### 論理項目

executed_at（取引日）、name、code（任意）、kind（buy/sell）、quantity、price、fee（任意/不明可）、tax（任意/不明可）、account（NISA/特定/一般）、asset_type（投資信託/日本株/米国株/ETF）、currency（JPY/USD）、price_unit（省略時は確認済み種別から投信10000・他1）、fx（約定時円換算為替）、fx_as_of、external_id（任意）。
価格・手数料・税額は同一の表示通貨で入力する。費用が別通貨の実CSVはそのまま対応済みではない。手数料に内包済みの税をtaxへ重ねて入力しない。
約定時為替がないUSD買付は円取得原価を不明とする。現在の評価為替を代用しない。
税/費用が不明なら決済金額は不明。既存transactions.amountがNOT NULLのため不明は空文字で保存し、計算時はNoneへ戻す（0ではない）。

## PayPay PDF/手入力

データ管理 → PayPay PDF・手入力・確認。テキストPDFは5MB/30ページまで。
抽出テキストと編集表を表示する。候補抽出は「Date:」や「取引日:」等の明示ラベルのみ。重複ラベルは曖昧として空欄にし、複数取引は行を追加して1ファイル分をまとめて確認する。
公式書面の複雑な表を自動解析したと断定しない。画像PDF/読取不能/暗号化の場合はOCRやパスワード要求を行わず、原本を見て手入力する。
PDFなしでも同じ表から取引を登録できる。初期口座は特定。保存対象はプレビューの確認済み全行で、抽出だけでは保存しない。
元PDF/CSV/全文テキストは保存しない。DBに保存するのは正規化取引、ハッシュ、設定、エラー等のみ。

## 重複・取消・修正

同一ファイルのSHA-256で再登録を防止。異なるファイルの同一取引も、証券会社/口座/外部ID、IDなしでは正規化した経済内容で照合する。
IDなしで同日同内容の別取引を区別できない場合は止める。実際に別取引なら検証済みの異なる外部IDを付ける。明細の数量を勝手に合算しない。
取消済み取引を再アップロードして復活させず、元のバッチの復元を使う。重複スキップだけのバッチは新たな取引を所有しないので、そのバッチを復元しても元取引の取消を覆さない。
修正は既存IDを維持し、変更前/後をtransaction_revisionsに保存。修正前の自然識別もaliasesに残し、古いファイルの再取り込みで元明細が復活しない。
取消/復元は状態変更と監査イベントを同じトランザクションで保存する。売却超過を生む取消・修正は拒否し全変更をロールバックする。

## 参考原価・残高

利用者が初期残高0からの全履歴であると確認した口座/商品だけ、取引から参考数量を計算する。不完全履歴なら初期数量/原価を推測せず不明とする。
買付原価＝（数量×単価÷価格単位＋別途手数料＋税額）×約定時為替。
売却対応原価＝売却直前の参考原価×売却数量÷売却直前数量。
参考売却損益＝（売却総額−手数料−税額）×売却時為替−対応原価。
これは税務上の公式損益ではない。同日売買で時刻がなく順序を確定できない場合は原価・売却損益を不明とする。正しい時刻があればISO日時等で入力する。
取引単価は現在価格として使わない。取引由来残高の現在評価は保有資産から別の価格/評価為替を入力する。
手入力現金/外部拠出額は自動更新しない。過去の資産スナップショットはその当時の記録として保持し、取消で書き換えない。

## 積立・分析

取り込み時に明示指定した買付だけを積立実績に加える。取消で除外、復元で再計算。同日同社同額の手入力実績と重なる登録を拒否する。未指定買付・未登録支出は予算分析の対象外と表示する。
商品分類/年率コストをデータ管理で入力すると、AI分析で集中しきい値・費用しきい値と比較し理由を表示する。未知費用を0にしない。投信の内部構成なしに実質重複を断定しない。
