# ホームのAI投資候補ランキング

## Windowsで使う

1. 使用中のアプリを停止します。元のフォルダ・バックアップは残してください。
2. 最新版の `自動更新.bat` を実行し、使用中のアプリフォルダを選びます。[更新手順](windows_auto_update.md)
3. 更新完了後に開いた新しいフォルダの **起動.bat** をダブルクリックします。
4. まず元の保有資産が表示されることを確認します。ホームの **AI投資候補ランキング・上位10件** に、保存済み候補と更新状態が表示されます。
5. J-Quantsキーは引き継いだ `.streamlit/secrets.toml` を使います。キーの値は表示・記録しません。読めない場合はAI銘柄探索画面の [キー診断](jquants_key_troubleshooting.md) を確認してください。
6. 購入単位、未保有フィルター、商品種別を選べます。候補の根拠・使用日・出典・リスク・NISA区分・購入条件を確認し、必要ならウォッチリストに保存します。候補は保有資産へ加算しません。
7. SBI取扱い・単元未満株可否・通常単位は、既存のAI銘柄探索の公式資料に基づく購入条件から登録します。ホームの費用欄では、銘柄と購入単位ごとに確認した手数料・スプレッドを登録できます。無料と確認した場合も0を明示してください。不明の空欄は0として扱いません。

手動起動する場合はapp.pyのフォルダで以下を実行します。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

## バックグラウンド更新

- アプリ起動・Streamlit全体の再実行時にローカルのキャッシュとジョブを確認し、期限切れの取得を別スレッドで進めます。ホームの表示処理からHTTP通信は実行しません。キーがない場合もホームと既存機能は使えます。
- 作業スレッドはStreamlit APIを呼ばず、専用のSQLite接続を使います。プロセス内でDBごとに1スレッド、SQLiteの15分リースで複数プロセスからの重複処理も抑止します。期限内の成功キャッシュは再取得しません。
- 株式一覧、価格、財務・指標、配当計算は通常24時間。設定済み公式一覧は停止情報15分・NISA対象24時間。公式資料の同期も起動時の表示とは別に実行します。手動の取得ボタンは従来どおり明示操作です。
- 多数の銘柄は段階取得します。公式ルールとウォッチ銘柄の更新を優先します。無料APIで市場全体を瞬時に更新するものではありません。最初はデータ不足の候補が多く、更新が進む間も取得済みの範囲を表示します。
- 429はRetry-Afterの秒数/HTTP-dateを尊重し、60秒から最大1時間の指数バックオフを併用します。このプロセス内で同じキーの実通信を60秒に5回までに制限。バックオフ状態・次回試行時刻はDBに残るため、Streamlit再実行で直ちに連打しません。別のPCの利用回数とは共有できません。
- 更新失敗時に前回の成功データを消しません。最終成功日時と最終試行日時を別々に表示し、失敗状態の価格は現在の評価に利用しません。日時表示は日本時間です。ホームの候補欄は30秒ごとにキャッシュを読み直します。
- サーバープロセスを終了するとスレッドも終了します。Windowsサービスの追加、クラウド公開、証券会社への自動発注は行いません。

## 評価ルール ranking-v2

| 軸 | 配点 | 計算 |
|---|---:|---|
| 割安性 | 20 | PER:15倍以下10/25倍以下6/超過2。PBR:1倍以下10/3倍以下6/超過2。各正値必須 |
| 成長性 | 20 | 売上・純利益成長率それぞれ0%で0点、20%以上で10点、間は比例配点 |
| 財務健全性 | 20 | 自己資本比率÷60×20、0〜20で制限 |
| 配当 | 10 | 利回り1〜5%=10、5%超=4、0超1%未満=2、明示0%=0 |
| 流動性 | 10 | 直近20観測日の終値×出来高の平均が1億円以上10、1000万円以上7、100万円以上3、それ未満0 |
| リスク | 20 | 年率変動率60%、観測最大下落70%へ向かって各10点から比例減点（各0〜10） |

すべて説明可能な簡易基準で、適正価格や値上がり確率のモデルではありません。流動性は実売買代金の代わりに終値×出来高を使った近似値。リスクは61点以上・60日以上の観測が必要です。株価トレンドも表示しますが加点対象ではありません。株価・PER/PBR・配当利回りの価格基準は7日以内、年次成長・財務は開示から365日以内を使用します。

全6項目と有効な非遅延価格、上場確認等が揃うまで総合点を確定しません。欠損と0点を区別し、配点の再配分もしません。確定銘柄だけを点数順に上位10件まで表示し、足りない件数を架空の候補で補いません。保留銘柄も根拠を確認・ウォッチ登録できます。

従来のAI銘柄探索のresearch-v1/auto-jp-v1の評価を削除せず、新ホームのranking-v2とはルール名を分けています。ルール間の点数は同一尺度として混同しないでください。

## 対象とデータ不足

日本株はJ-Quants一覧の普通株候補、ETFは利用者が商品種別を確認してJPYのETFとして登録したカタログを対象に、自動で価格・出来高・リスクを取得します。無料マスターの「その他」区分を無条件でETFと判定しません。未確認のETF/ETN/REITの網羅的な自動分類は未対応です。

ETFに個別企業の利益成長や自己資本比率を流用しません。ETFの構成資産を集計した割安・成長・財務指標の取得は未対応であり、ETFは価格/流動性/リスクの参考分析とウォッチ登録を提供し、総合点は保留します。

無料プランの12週間等の遅延値は過去の参考情報です。現在価格・現在の総合スコアにしません。そのため無料契約だけでは現在の評価済み上位10件を作れない場合があります。有料契約への自動移行や、欠損を生成AIで埋める処理はありません。財務・PER/PBRは契約権限に依存します。

## 予算・NISA

既存の月予算（未設定時7500円）から、手入力積立、積立指定済み購入、未指定の購入実績、未実施積立予定を差し引きます。確定残額が負なら投資可能額0、超過額を別表示。購入金額や為替が不明、手入力と取引に同日・同社・同額の曖昧な記録がある場合は残予算を確定せず照合を求めます。未登録購入は把握できません。元の積立画面の集計APIは維持します。

購入必要額は確認済み売買単位の株価×数量＋当該購入単位の手数料＋スプレッド、円未満切り上げの試算です。SBI取扱い・単元未満株可否・費用が確認できない場合は購入可能と断定しません。実際の約定価格・注文条件は購入前に確認してください。

NISAは従来の公式一覧照合と、確認日付き年間つみたて/成長、生涯総枠/成長枠の使用・予約額を利用します。公式一覧で対象が不明、個人の残枠が不明な場合は購入判定保留です。口座残枠の自動取得は行いません。[公式一覧の同期と制限](official_sync.md)
