# データ検証と評価履歴

## 最初の使い方

1. アプリを停止し、`自動更新.bat` で最新版に更新します。完成した新しいフォルダの `起動.bat` を開きます。
2. ホームで、今までの保有資産と積立額が表示されることを確認します。
3. 上部の **検証・評価履歴** を押します。ホームで表示した候補の評価が保存されています。
4. **確認する評価履歴** で銘柄と保存日時を選びます。
5. **公式資料と照合** で「参考終値」などの項目を選びます。
6. JPXや企業IRなど、ご自身が確認した公式資料の**同じ基準日**の値を入力します。価格は調整前/後、配当は予想/実績の違いも確認します。
7. 公式値の基準日、HTTPSのURL、資料名・決算期・ページを入力します。わからない数値は空欄、日付は「不明」にします。
8. 銘柄、単位、会計期間、連結区分、計算条件が同じ場合にだけチェックし、**照合結果を保存** を押します。
9. **評価の履歴・前回との差** で、評価時点の点数・計算式・値・日付・根拠、以前の評価との差を確認できます。
10. **検証記録を出力** から照合記録をCSV保存できます。各評価はJSONで詳しく保存できます。

ほかの銘柄を記録するときは **評価を新しく保存する** を開き、検索して選択し、保存します。一度に20銘柄までです。候補一覧にない商品は、先にAI銘柄探索で登録してください。現段階の履歴対象はホームの `ranking-v2` の日本株・国内ETFで、投信・米国株の別評価エンジンの履歴は含みません。

## 判定の意味

| 表示 | 意味 |
|---|---|
| 一致 | 同じ日付・確認済みの条件で数値が完全一致 |
| 許容差内 | 数値差はあるが、利用者が設定した丸め等の許容差以内 |
| 差異あり | 比較条件が揃ったうえで許容差を超える |
| 比較保留 | 取得値/確認値/日付が不明、日付が違う、または条件未確認 |

差は「取得値−公式確認値」。相対差はその差÷公式確認値の絶対値×100。公式確認値が0なら相対差を計算しません。欠損を0にはしません。許容差の初期値は0で、丸めなどの根拠がある場合だけ変更します。

財務データの基準日は通常、公表日です。決算期末や会計基準は、保存された財務入力の `period_end` / `history` と公式資料で別途確認してください。配当利回りを照合する場合は分子の配当年度・実績/予想、分母の株価日、株式分割の基準も一致させます。APIの公表指標とご自身で算出した指標を無条件に同じ定義としないでください。

公式URLと確認値は手動で記録します。アプリが資料をダウンロードして値や公式性を認証する機能ではありません。認証情報・クエリ・フラグメントを含むURLは受け付けません。URLへの自動アクセスはしません。

## 保存と既存データの保全

- 初回移行時、既存DBの横へ `.pre-evaluation-audit.bak` をSQLiteバックアップAPIで作成してからテーブルを追加します。既存バックアップは上書きしません。
- 新規テーブルは `evaluation_snapshots` と `data_verifications`。保有残高、積立、取引、APIキー、既存の計算式を変更しません。
- 評価時点の銘柄情報・価格履歴・財務の入力キャッシュ・使用した手動財務情報・公式照合結果・スコア・計算式・欠損理由・取得日時を記録します。更新処理と混ざらないよう短い同一DBトランザクションで評価・保存します。追加API呼び出しはありません。
- ホームに表示される評価済み上位10件と保留先頭10件が自動保存対象です。検索や商品種別で対象が変わります。全銘柄の履歴を網羅する機能ではありません。
- 同じ銘柄・ルールについて、直前の記録と同じ内容なら同日の再実行では追加しません。翌日、または入力/状態が変われば追記します。一度変化して元へ戻った場合も変化を残します。
- 候補やウォッチを削除しても評価履歴は消しません。履歴に対する確認値は登録後も過去時点の値のままです。
- 照合値の訂正は追記し、訂正元IDを残します。同じ項目を同時に別画面で訂正した場合は、最新記録を確認するまで保存を拒否します。
- CSVはUTF-8 BOM付き、セルの式実行を防止。履歴のJSONにはAPIキー・口座認証情報を参照しません。履歴・手動メモは既存のローカルDBと同じ保管先です。
- 記録は自動削除しません。価格履歴も保存するので長期利用でDBが大きくなります。アプリを停止してDBをバックアップしてください。

## この段階で確認できること・できないこと

無料プランの古い価格・財務の参考値も、同じ過去の基準日の公式資料と照合できます。現在の評価に使えるかは別の `usable` フラグで残し、遅延価格や失敗した取得を「現在の評価」に格上げしません。照合結果から元データや配点を自動修正することもありません。

保存を始める前の評価は復元しません。現在取得した過去データで過去の評価履歴を捏造しません。これは今後の検証基盤であり、将来の利益、値上がり確率、売買戦略の有効性を示すバックテストではありません。利益の事後検証、配当再投資を含む収益率、上場廃止銘柄を含む市場全体での検証は未実装です。

また、ETFの構成資産の指標取得、有料プラン用の一括設定、公式サイトの現行様式との接続検証、Windows実機検証は今回の対象外です。

## 独自性を育てる順序

1. **まず情報の正確さを測る**：10〜20銘柄を同じ日付の公式資料と照合し、取得ミス・定義の違い・更新失敗を区別します。単純な一致率だけで品質を判断せず、項目と原因ごとに調べます。
2. **少額投資の実行条件を揃える**：7,500円から既存積立を引いた残額、SBIの単元未満株条件・費用、NISA残枠が揃って初めて候補を絞ります。
3. **買わない判断も記録する（次期）**：「予算不足」「分散が悪化」「根拠不足」で見送った理由を残し、購入候補と同じ条件で振り返れるようにします。
4. **提案の変化を知らせる（次期）**：点数の上下だけでなく、決算・配当・価格・データ失効など、何が判断を変えたかを整理します。今回の保存入力と差分表示が土台になります。
5. **実績と比較する（次期）**：既存積立だけを続けた場合と候補追加を、当時利用可能だった情報・同じ投入金額・費用込みで比較します。先読み・生存者偏りを避け、別期間でも検証してから配点を見直します。

独自性の方向は「この人の予算・既存積立・不明事項を踏まえて、判断の根拠と変化を追えること」です。未検証の精度向上や新規性を保証しません。利用目的は自分用の意思決定支援で、発注は利用者が証券会社で確認して行います。
