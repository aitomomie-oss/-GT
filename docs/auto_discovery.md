# 日本株の自動探索

既存の7番目の「AI銘柄探索」の上部に追加。元の6画面、候補比較・ウォッチリスト、保有資産、積立計算は維持しています。

## Windowsで使う

1. アプリを停止し、使用中の `local_data/assets.db`（旧版は `data/assets.db`）をコピーして保管します。
2. 更新版を別フォルダに展開し、DBを同じ相対位置へコピーします。古いフォルダは残してください。
3. 新版の `.streamlit` フォルダへ、既存の `secrets.toml` を自分のPC内でコピーします。キーをチャットやGitHubへ貼らないでください。
4. キー名はトップレベルの `JQUANTS_API_KEY`、または `[jquants]` 内の `api_key` に対応します。ファイルはGitの対象外です。既存ファイルを上書きする必要はありません。
5. 依存ライブラリをインストールして起動します（README参照）。「AI銘柄探索」→「日本株の自動探索」を開きます。
6. 基準日を選び「銘柄一覧を取得・更新」を押します。無料プランは初期値の約12週前を使い、契約のデータ提供期間に合わせて調整します。
7. 業種、普通株、未保有の条件で絞り、「次の3銘柄の価格・リスクを取得」を押します。繰り返すと未取得・期限切れの銘柄へ進みます。
8. 詳細を選ぶと株価履歴、登録財務、算式、基準日、保留理由を確認できます。「候補に登録」後は従来の候補詳細で財務・購入条件・ウォッチ登録を管理します。

secrets.tomlを優先し、未設定の場合のみ既存の環境変数を互換利用します。不正なsecretsファイルの内容は表示しません。APIキーの入力欄・表示・DB保存はありません。

## データと評価

- J-Quants V2の `/equities/master` と `/equities/bars/daily` を使用。銘柄一覧は同じ基準日で24時間キャッシュし、正常な全ページ取得後のみ一覧を更新します。コード単位で差分upsertします。
- 普通株候補は市場コード0111/0112/0113と業種コードから分類。その他は「ETF・ETN・REIT等/区分要確認」。個々のETF/ETN/REITを確定する商品マスターは未接続です。
- 一覧から消えた銘柄は削除せず `not_in_latest` にして通常探索から除外。これは上場廃止の断定ではありません。取引停止データは未取得なので売買可能と断定しません。
- 価格は1回3銘柄（サービス上限5）、試行後24時間スキップ。認証・権限・制限・ネットワーク等のエラーが発生したら即座にバッチを中断します。失敗状態と前回成功データを分けて保存します。
- 一覧・価格は探索専用テーブルに保存。DB移行前に既存DBを `.pre-auto-discovery.bak` へ一度だけSQLiteバックアップします。既存テーブルの削除・既存保有や取引の更新はしません。
- 新ルール `auto-jp-v1`: 割安25、成長25、財務20、トレンド15、配当15。算式は画面の「評価基準・計算式」に全表示。
- 充足率は、必要な値をすべて満たした評価軸の配点合計。欠損をゼロと偽ったり、残配点を他の軸へ再配分したりしません。全軸を満たすまで総合評価保留。
- 財務は従来の候補詳細に登録した出典・基準日付きデータを優先し、未登録時はAPI取得の通期財務を参照（有効期間365日、更新失敗・遅延は無効）。株価は7日以内かつ非遅延。無料プランの遅延価格は株価グラフと参考価格としてのみ表示し、現在価格・現在の総合スコアには使いません。
- ランキングは絞り込み対象全体の評価点順（50銘柄ずつ表示）。全市場の全銘柄取得を強制しません。市場・業種の偏りを考慮した適正価格モデルではなく、単純な説明可能ルールです。
- 同業比較は絞り込み対象内の同一業種。短期・長期リスクの説明は一般的事項で、個別企業に関する根拠のない強み・将来予測は生成しません。
- 積立実績・予定を差し引いた既存の残予算を表示。NISA・SBI取扱・少額購入条件は不明のまま確認事項として扱います。候補詳細に確認値を登録すると既存の購入可能性判定を使えます。

## 未対応・実機未検証

配当利回りの自動計算、事業説明文、自社株買い、取引停止の自動判定、ETF等の厳密な細分類、NISA対象リストの自動同期、証券口座からのNISA残枠自動取得は未対応。財務・PER/PBRは契約で取得できない場合は保留です。

実APIの認証接続とWindows実機は未検証。自動テストは架空レスポンスと一時DBで検証します。APIキーなしでも既存の手入力機能は使用できます。


## 財務APIと追加された予算連動

- 公式Pythonクライアントの仕様を確認し `/fins/summary`（code）と `/equities/valuation`（code/from/to）を実装。1銘柄ずつ明示的に取得し、24時間キャッシュ。契約権限による403等は隠さず状態表示します。無料契約で全項目を取得できるとは限りません。
- 財務は通期FYの公表値を表示。同一DocType・連続する決算期だけ売上/純利益の成長率を計算し、前期ゼロ・負値は成長率を作りません。自己資本比率は公表自己資本÷総資産。PER/PBRはvaluation APIの値を使い、7日超の指標は無効。配当年額は原資料の履歴に表示し、株式分割の基準一致未確認なので利回りへ自動変換しません。
- 新しい投資可能額は max(0,月予算−積立実績−未実施予定)、超過額は max(0,積立実績＋未実施予定−月予算)。既存画面の差引残額計算は維持します。今月の予算を探索画面でも変更可能です。
- 単元株/単元未満株の条件は、SBI公式ページを確認した利用者が転記。NISA適格性は金融庁・投信協会・JPX・SBIの公式資料のURLと確認日を記録します。URLドメインの検証であり、ページ内容や銘柄ごとの適格性を自動認証する機能ではありません。推定値を適格性として登録しません。
- URLは認証情報流出を避けるため、クエリー・フラグメント・埋込ユーザー名/パスワードを受け付けません。公式ページの通常のパスを入力してください。
- 日本株は成長枠の確認が必須。NISA年間つみたて/成長、生涯総額/成長の使用済額と未約定予約額を別々に記録します。未入力は不明でありゼロ扱いしません。新NISAの使用枠は取得額基準で確認し、売却した当年に枠が戻ったと解釈しないでください。年間は暦年、31日超の確認値は保留。NISA枠へ予約分を登録する際、使用済額に含めた金額を再び予約額へ含めないでください。
- 予算不足なら翌月以降の検討候補。NISA残枠・価格・単元未満取扱いが不明なら購入判定保留。購入前の本人確認は必須で、発注や予約消費の自動更新はしません。
- 保有日本株の業種集中はコードで照合し、分類可能な直接保有のみを集計。投信/ETF内部の構成情報は不明と明示します。
- 新規投資の資産配分と5/10/20年の比較は仮定計算。外部予算の投入を仮定して証券評価額のみを比較（口座現金を二重計上しない）。既存積立だけの参考線、既存資産へ同額追加する線、新規候補へ一度だけ配分する年率−3/0/3/5%の線を表示。両案で同じ投入金額の比較と、投入金額が異なる参考線を区別します。既存画面のシミュレーションは変更しません。
