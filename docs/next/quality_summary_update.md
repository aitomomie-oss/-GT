# データ品質サマリーの追加

## 前段階の確認

ユーザーから日別一覧の表示とCSV保存・閲覧の成功を受領しました。独立した公式資料との価格照合は未完了です。続く「進めてください」で、保存済み評価の不足・古さ・取得失敗・未照合を確認する機能を追加しました。

## 実装

「検証・評価履歴」の上部に「データ品質サマリー」を追加。対象評価、指標不足、期限超過、取得失敗、未照合・比較保留、差異ありを表示します。理由・優先確認事項の一覧、状態別フィルター、表示行のCSV出力を備えます。

対象は銘柄コード・評価ルールごとの最新の保存評価です。現在の全候補・全キャッシュの評価結果とは区別します。保存時の不足/取得状態と、今日時点の基準日の経過を分けて確認し、現在の更新ジョブの失敗件数は別集計します。詳細は [docs/data_quality.md](../data_quality.md)。

変更するアプリ関連ファイルは5個です。

- `src/services/data_quality.py`：読取専用の集計・CSV。
- `src/ui_data_quality.py`：サマリー・フィルター・固定理由の表示。
- `src/ui_evaluation_audit.py`：サマリー表示の呼出し。
- `tests/test_data_quality.py`：15件の追加テスト。
- `docs/data_quality.md`：操作方法、対象と判定の限界。

固定参照：`793d725`（更新ツールは完全なコミットIDと各ファイルのSHA256を保持）。APIキーの読取、API通信、再試行、DBの書込・移行、スコアや資産計算の変更は行いません。サマリーの件数は重複する区分を含み、正確性を表す点数や一致率とは扱いません。未来日・日付不明は期限内と表示せず、0点と欠損は区別します。照合結果は最新の手動記録であり、アプリによる資料の真正性認証ではありません。

## Windowsでの適用

[apply_quality_summary.py](apply_quality_summary.py) は、確認済みの評価履歴開発コピー `MY_AI_ASSET_NEXT_evaluation_dev_20261020_081047_0f20662e` にだけ適用します。8506番のアプリを起動したPowerShellでCtrl+Cを押して停止してから、確認済み共有Python環境で実行します。

更新ツールは基準コードと新規ファイルの不存在を確認し、固定コミットの5ファイルを取得・SHA256照合します。対象内 `backups/before_quality_summary_<日時>_<識別子>` へSQLiteオンラインバックアップとコード・設定・起動バッチを保全。秘密設定がある場合は私的な回復バックアップにだけ複製し、テストコピーには持ち込みません。

別のテストコピーで全262テストを実行し、元DB/コピーDBの全定義・全行が変わらないことを確認してから5ファイルだけを差し替えます。途中失敗した場合は差し替えたコードを戻し、バックアップを保持。改変済みコードや取得内容の不一致は拒否し、適用済みの再実行は取得・書込を行いません。元アプリの起動バッチ・設定・DBへの変更はありません。

成功時は `QUALITY_SUMMARY_READY` とバックアップ先を表示します。その後は同じ `評価履歴_開発用起動.bat` で8506番に再起動し、「検証・評価履歴」の上部を確認します。日別一覧・既存履歴・手動照合の画面は維持します。

- [quality_update_checks.py](quality_update_checks.py) の7件成功（15.93秒）。日本語パス、適用、私的バックアップ、元DBのバイト不変、秘密設定のテストコピーへの非持込、起動バッチ不変、繰返し時の非取得、取得/既存改変/対象違い/DB欠損の拒否、テスト失敗時の非適用、途中失敗時の復旧とバックアップ保全を検証。
