## Windowsで実施するバックアップの基準（手順準備のみ）

1. 待受ポート・PID・作業フォルダーを照合し、使用しているアプリとDBを確定する。3版が同時に見つかっているため、他のDBを同じものとみなさない。
2. 確認したアプリをCtrl+Cで停止する。他の版が同じDBを使っている場合は、その版も個別に確認してから止める。ブラウザーを閉じるだけでは背景ワーカーは止まらない。
3. 元アプリの外側に新しい日時付きバックアップフォルダーを作る。既存バックアップを上書きしない。コード/設定と、確定したDBを保全する。外部パスのDBを忘れない。
4. DBは標準sqlite3の `mode=ro` URIでソースを開き、SQLite backup APIで新規バックアップを作る。`src.db.session.connect()` を呼ばない。WALのコミット済み情報を含める。
5. 元とバックアップでquick_check、foreign_key_check、テーブル/列の一覧と表ごとの件数を確認する。異常や既存の外部キー問題があれば記録して止まり、勝手に修復しない。未知の旧テーブルも保全する。
6. `.streamlit/config.toml` と使用中の秘密設定をPC内のバックアップへ複製する。秘密設定を複製した場合は、値やハッシュを報告書に出さず、元とのバイト一致の成否だけを記録する。共有フォルダーやGitへ置かない。
7. グローバルStreamlit設定が実参照元なら、プロジェクトのsecretsだけで完了扱いにしない。環境変数由来のキーをTOMLや平文ログへ勝手に書き出さない。
8. バックアップDBを別の一時パスへ復元し、整合性とスキーマ・件数を再確認する。本番DBへ復元しない。
9. バックアップ先・検査の成否・使用したアプリの版だけを記録する。鍵・銘柄明細・口座情報をチャットやGitへ送らない。

既存 `tools/windows_update.py:backup_database()` には読取専用ソース＋SQLite backup API＋quick_checkの実装があります。236件の基準テストには、この機能のWAL保全テストを含みます。ただし、実アプリを更新する `prepare_release()` や自動更新.batを今回のバックアップ目的で実行してはいけません。現在のコードの関数を使う場合も、Windows側の版を先に確認します。

秘密設定のバックアップそのものには元のAPIキーが含まれます。これはPC内での復旧専用コピーであり、画面・ログ・調査報告・Gitへの出力には使いません。実DBと秘密設定のZIPをこのチャットへアップロードする必要はありません。

## バックアップ専用の補助スクリプト（用意済み・Windowsでの実行は確認待ち）

`docs/next/backup_windows.py` はPython 3.12標準ライブラリだけで動く単独ツールです。既存アプリの起動・インポート・更新・DB移行、API通信は行いません。調査範囲のバックアップを実施するために追加し、既存のapp.py、pages、src、tests、起動バッチは変更していません。

- `--app` で指定したフォルダーについて、今回照合した4ファイルのハッシュを再確認します。違えば開始しません。
- 元DBとプロジェクト設定が存在しなければ止まり、空の元DBを作りません。
- 保存先は `%USERPROFILE%\MY_AI_ASSET_Backups\MY_AI_ASSET_NEXT_日時_識別子`。アプリや旧バックアップを上書きせず、バックアップ内に全件除外の.gitignoreも作ります。
- 元DBは `mode=ro` とquery_onlyで開き、同じ読取トランザクション内でSQLite backup APIによりコピーします。WALのコミット済み情報を含め、quick_check、foreign_key_check、全テーブルのスキーマと件数を照合します。
- バックアップDBからさらに `restore_check/assets.db` を作り、同様に検証します。本番へ復元しません。
- コードと起動バッチ等も `code/` へ複製します。.venv・.git・DB・秘密設定・.env・アップロードはコード複製から除外し、許可したアプリのディレクトリーだけをコピーします。リンクやジャンクションがあれば止めます。
- プロジェクトのsecrets.tomlとconfig.tomlは復旧専用に `.streamlit/` へコピーし、バイト一致を確認します。報告JSONと画面にはキーの内容・長さ・ハッシュを出しません。
- TOMLの対応項目を読み、確認済みのcredentials.pyと同じローカル読込条件に合うかを真偽値だけで報告します。API認証の成功を意味しません。NOの場合は設定を保全したまま参照元調査を続けます。
- 失敗時は例外本文・元データを表示せず、安全な失敗区分を出します。途中までのバックアップと報告を残し、元アプリを修復・初期化しません。

Windowsのアクセス権はユーザープロファイルの権限を継承します。バックアップは暗号化されず、秘密設定を含みます。PC内の復旧専用として管理し、Gitやチャットへアップロードしません。

### 補助スクリプトの検証

Linux / Python 3.12で架空の一時データを使い、`python docs/next/backup_checks.py -v` の8件が成功しました。WAL・未知の旧テーブル・特殊なテーブル名の保全、別パス復元、繰返し時の非上書き、元ソース変更時の中止、元DB未存在時の非作成、壊れた秘密設定の非漏えい、破損DB/既存の外部キー異常時の保全、CLIエラーの非漏えいを確認しています。これは既存アプリの236件とは別の補助ツール検証で、Windows実機での成功を意味しません。
