# MY AI ASSET — Phase 2

Windows PC内で使う個人向け資産管理アプリ。Python 3.12 / Streamlit / SQLite。
SBI証券NISAとPayPay証券の特定口座を初期設定。証券会社の認証情報は保存せず、外部AI送信・自動売買・クラウド公開は行いません。

**取引履歴CSVがなくても、初期残高の手入力だけで資産管理を開始できます。**

## Windowsで起動

Python 3.12（Python Launcherを含む）をインストールし、ZIP展開後の `my-ai-asset` フォルダでPowerShellを開きます。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

導入後は `起動.bat` でも起動できます。ターミナルのLocal URLをブラウザで開き、終了はCtrl+C。
127.0.0.1以外へバインドせず、インターネット公開しないでください。

## CSVなしで始める

1. 「保有資産 → 新しい保有残高を登録（初期残高・CSV不要）」を開く。
2. SBI/PayPay、口座、商品名、数量、現在価格、参考取得原価、評価日を入力して保存する。
3. 取得原価・現在価格・USD為替が不明なら空欄にするか不明チェックを選ぶ。数量だけでも保存できます。必要情報がない評価・損益は「計算不可」で表示します。
4. ホームで集計を確認。「データ管理」で口座の現在現金・累計外部拠出額を必要に応じて入力する。

投信は口数と1万口価格、日本株/米国株は株数と1株価格、ETFは口数と1口価格。USDは現在の円換算為替も入力します。
PayPayを選ぶと新規登録の初期口座は特定、SBIはNISAです。口座区分は修正可能で、SBI以外のNISA指定は警告します。

あとから取引CSVを登録しても初期残高へ加算しません。同じ口座・商品は直接残高を優先し、数量差を照合表示します。コードが空でも同一名称等の候補を保留し、二重計上を防ぎます。

## SBI証券の取引CSV

「データ管理 → SBI取引CSV・列マッピング」で利用者が公式画面から取得したファイルを読みます。
実際のヘッダーを表示し、取引日・銘柄・売買・数量・単価・手数料・税額・口座等を対応付けてプレビューを確認します。投信/日本株/米国株/ETF、JPY/USDに対応する論理モデルです。

**実際のSBI CSVは未提供のため、固定の会社様式を確認済みとはしていません。** 現在の経路は利用者が実列を確認する汎用マッピングです。未知の区分・不正値は停止します。

手数料・税額は単価と同じ表示通貨に統一し、手数料に内包する税を重ねて入力しないでください。異なる通貨が混在する実ファイルを自動換算する機能はありません。
数値の桁区切り・通貨記号を自動除去しません。書面で確認して整形してください。未知の費用や約定時為替は不明のまま登録できます。

## PayPay証券の書面

「データ管理 → PayPay PDF・手入力・確認」。テキストPDFの文字を抽出し、候補を編集表へ提示します。表の全行を元書面と照合してから承認してください。
複数取引は編集表で行を追加し、1ファイル分をまとめて登録します。
画像PDF・暗号化・読取不能では自動OCRやパスワード要求をせず手入力へ切り替えます。PDFなしの取引入力も可能です。

実際のPayPay書面レイアウトは未検証。候補抽出は明示ラベルに限る補助機能で、公式書面の複雑な表を自動で正確に解釈すると保証するものではありません。

詳細な項目・変換例・会計条件: [phase2_imports.md](docs/phase2_imports.md)。従来の残高CSV: [import_formats.md](docs/import_formats.md)。

## 重複・取消・修正

- ファイルのSHA-256と取引識別により、同一ファイル/同一取引の二重登録を防止します。ファイル内重複や曖昧な同日同内容は確認対象にし、推測で合算しません。
- 外部IDがある場合は証券会社・口座と合わせて識別。IDなしの同日同内容の別取引は区別できないので、必要なら確認済みの異なる取引IDを指定します。
- 取り込みは全件一括。1行でも問題があれば取引・商品等の途中レコードを残さず、エラー履歴だけを保存します。読み取り前段の検証エラーは画面の保存ボタンで履歴化できます。
- 「取引取り込み履歴」で件数、エラー件数、重複件数、日時、マッピングを確認し、チェック後に取消/復元できます。物理削除はしません。
- 売却超過を生む取消/修正は拒否します。依存する売却を先に取消すなど原本に沿って処理してください。
- 取引修正はプレビュー確認後に保存し、変更前/後の監査履歴を残します。修正前データを再取込して復活させません。
- 手入力残高・現金・外部拠出額・過去の資産スナップショットは取消で変更しません。

## 取引からの原価・円換算

初期残高0からの全履歴であることを明示確認した口座/商品だけ、参考数量・移動平均原価・参考売却損益を計算します。不完全履歴なら初期数量や取得原価を捏造しません。後から完全性を確認する操作も可能です。

取引単価は現在価格ではありません。取引由来残高の時価評価は、保有資産画面で現在価格と評価為替を別に入力してください。
約定時為替が不明なUSD買付は円取得原価が不明です。同日売買の時刻/順序が確定しない場合、原価・売却損益は計算不可になります。税務上の正式損益ではありません。

買付を積立実績へ含めたい場合は取り込み時に明示指定します。指定分と手入力実績だけを月予算に集計します。取消で除外、復元で再反映します。同日同社同額の手入力/取込済み実績がある場合は二重計上を止めます。

現金/外部拠出額は口座別の手入力参考値のままです。取引からの自動再構築や累積運用損益の正式計算は未対応。参考取得原価、購入額合計、外部拠出額を区別してください。

計算・保存はDecimal/TEXT、未取得はNone（旧transactions.amountの不明値のみ空文字で保存）。[計算仕様](docs/calculations.md) を参照。

## サンプル・保存・バックアップ

`sample_data/` は架空データだけです。Phase 2の架空CSV/PDFと設定例は `sample_data/phase2/`。会社の公式フォーマットではありません。
画面の「架空サンプルを追加」は直接残高/積立が空の場合に使用し、使用中は「架空」と表示します。

デフォルトDBは `local_data/assets.db`。旧 `data/assets.db` だけがある場合は継続使用します。実運用には別DBを指定できます。

```powershell
$env:MY_AI_ASSET_DB = 'C:\Users\YOUR_NAME\Documents\my-assets.db'
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

DB・アップロード・バックアップ・`.env` はGitから除外します。元アップロード/PDF全文は保存せずメモリー処理します。ログに明細全文や口座番号を出しません。DB/バックアップ自体は暗号化されないのでPCのアクセス権で保護してください。

完全バックアップはアプリ停止後に使用中DBをコピーします。復元も停止後に現在DBを保管してバックアップへ置き換えます。CSVやバッチ取消/復元は完全DBバックアップではありません。画面からの完全バックアップ/復元はPhase 4予定。

旧holdings方式は `.pre-phase1.bak`、Phase 1スキーマは `.pre-phase2.bak` を移行前に保存します。既存の保存情報を消さず追加スキーマへ移行します。バックアップは上書きしません。古いREALの精度以上に数値を復元することはできません。

## ライブラリ・構成

Streamlit（画面）、pandas（表）、SQLAlchemy（スキーマ）、Pydantic（入力検証）、Plotly（グラフ）、pytest（検証）、pypdf（ローカルのテキストPDF抽出）を使用します。SQLite操作は標準ライブラリ、会計はDecimal。有料API不要です。

指定の `src/db`、`src/services`、`src/importers`、`src/utils`、`pages`、`sample_data`、`assets`、`docs`、`tests`、`local_data` 構成を維持します。[architecture.md](docs/architecture.md) を参照。
